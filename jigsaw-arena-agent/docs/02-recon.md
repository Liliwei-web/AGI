# 02 · 黑盒侦察：把接口能力探到底

> 本文记录解题最初阶段（第 1–3 轮迭代）。这一阶段的产物不是解法，而是一张"哪些路根本走不通"的清单。
> 后面所有解法之所以能少走弯路，都是因为这一阶段把"想当然"全部测掉了。

## 1. 当时的处境

手里只有一个能连上的仿真器：

- **没有任务源码**，没有接口文档，没有题目说明。
- 唯一可用的信息只有两处：一帧**物体列表**（每个 object 的 `object_id` / `place_location` / `rotation` / `world_aabb` / `color` / `shape`），以及一张**第一人称 RGB 截图**。
- 本地 `train` 模式能拿到 `is_right` / `jigsaw_score` / `score`；`test` 模式只落一个加密的 `result_*.bin`，本地读不出分数。

所以第一阶段的目标只有一个：**把接口能力探到底**，先确定"哪些观测量真实存在"。

## 2. 假设

任何"看图判断"的解法，都隐含依赖下面四条假设中的至少一条：

| 编号 | 隐含假设 | 如果成立，可以做什么 |
| --- | --- | --- |
| H1 | 物体的 `color` / `shape` 字段携带真实图案信息 | 直接按颜色把块匹配到槽位 |
| H2 | 相机可以被瞄准、并且可以稳定复现 | 把 3×3 板面标定成固定像素框，一次标定长期复用 |
| H3 | `put_down_sth` 会反馈"放得对不对" | 试放 + 读返回码，完全不需要视觉 |
| H4 | 已经放下的块可以再拿起来 | 局内做多组试排实验（等价于 undo） |

这四条假设**没有一条写在文档里**——它们只是"看上去应该有"的常识。所以实验设计的原则是：每条假设找一个**最小可证伪实验**，即"如果它成立，就必然出现某个信号"。

## 3. 实验设计

用一个脚本化探针 agent（`jigsaw_probe_agent`，不经 LLM、按固定 FSM 依次执行）挂上不同的环境变量开关，每次只测一件事，并把原始帧与物体列表全量落盘到 `logs/recon/probe_<agent_id>.jsonl`（附 `.jpg` 回看图）。

| 探针 | 测什么 | 判据 |
| --- | --- | --- |
| `PROBE_SCAN_ONLY` | 原生分辨率抓帧；物体列表里有没有颜色字段 | 逐块 `color` / `shape` 是否非 `Unknown` |
| `JIGSAW_CALIB` | 同站位连拍 5 张 | 帧间 mean\|diff\| 是否接近 0 |
| `JIGSAW_AIM` | 同站位只改瞄准点 | `look_at_location` 与 `look_at_object` 是否改变画面 |
| `JIGSAW_TURN` | 0,+10…+50,-50,+10…+50 扫两轮 | 回到同一名义角度的两帧是否几乎相同 |
| `PROBE_COLORSCAN` | 站到每个目标正前方 40cm，裁中心 120px 直方图 | 6 个已放块采样能否复现画面语义 |
| `PROBE_FACE` | 把待放块拿在手上、对准后采样 | 手上能否看到块的图案正面 |
| `PROBE_PLACE` | 同一空槽"放入前 / 放入后"采样 | 图案正面何时可见 |
| `PROBE_UNDO` | 放好 → 再 `move_and_take_object` | 手上状态与板面状态是否真的回退 |
| `PROBE_EVAL` | 指定排列实跑一局，读官方本地评分 | 分数到底对什么敏感 |

## 4. 原始数据

**H1（结构化颜色字段）——不成立。**

- 物体列表里所有拼图块（含参考大图 object 16）的 `color` / `shape` 恒为 `Unknown`，**API 没有逐块颜色字段**。
- 原生抓帧为 2048×1000；而显式传 `width=1280, height=720` 会拿到 **2560×720 的全景图**，板面严重畸变，几乎无法用于判断。

**H2（相机可瞄准/可复现）——不成立。**

- 同一站位、只改 `look_at_location` 的瞄准点连拍，画面**逐像素几乎相同**（mean\|diff\| 2–3）；而只改站位（stand 的 Y）画面立刻大变（mean\|diff\| 29）。
- 交叉复核旧数据一致：`arr_right_cell_166_88` 与 `arr_right_cell_166_110`（同站位、不同瞄准）差异仅 1.24。
- 结论：`look_at_location` / `look_at_object` 基本**不改变第一人称取景**；取景由「站位 + 上一次行走产生的朝向」决定。
- `turn_in_degree(degree)` 确实会改变画面（连拍文件大小 127K→88K 明显变化），但**重复性差**：两轮扫描中回到同一名义角度的两帧，mean\|diff\| 仍是 15–21，与"不同角度帧"同量级。
- 唯一稳定的情形：**不发移动/转身指令、原地连拍**时画面稳定（同相位 9 张 mean\|diff\| ≤ 3）——只够做同相位内的比较，不够做定位。
- 近距看板取景还踩过一个坑：刚做完 `put_down_sth` 直接 `move_to_location` 到近距站位（返回 success），取景会整体偏出板面，**4/4 全废**；必须先走回出生点、再站近距位，取景才正确。

**H3（放置有错误反馈）——不成立。**

- 故意用一个错误角度请求放入：`put_down_sth(target_rotation.yaw=194)` 返回 `success`，块真的被锁定在槽内（最终角被规范化记录为 `yaw=14 / pitch=-90`），**不弹回、不吸附、不报错**。
- 也就是说"试放看错"这条路是死的：错误放置只会真的占住槽位。

**H4（可撤销）——成立，而且是整条链上最值钱的一条。**

- `PROBE_UNDO` 序列实测：`has_object_in_hand` 基线为 `False` → `move_and_take_object(8)` success、手上 `True` → `put_down_sth((837,155,99), auto_rotate=True)` success、手上 `False` → **对已入槽的块再 `move_and_take_object(8)` 依然 success、手上 `True`**，且回看帧里该块已从板面消失、槽位重新空出。
- 另外确认 `auto_rotate=True` 的语义：放置后该块 `rotation.yaw = 110.99999237060547`，与当局板面基准 yaw 完全一致——**"转多少度"不需要搜索**，剩余自由度只有"哪块进哪槽"（3! = 6 种）。

**补充事实（后来都用上了）：**

- **每局板面朝向随机**：已见 63° / 81° / 104°，同一局内 9 块的角度完全一致（含 6 块已放 + 3 块待放）→ 控制器必须从首帧自己算"众数 yaw"，不能写死。
- **几何布局每局一致**：X=837，Y 行 155/166/177，Z 列 88/99/110（格距 11），待放块出生在 Y=209 行。
- **远距可见物体列表不稳定**：同一出生点两次回看，一次含板面块、一次不含 → 不能用它做板面校验。
- **本地评分语义（`PROBE_EVAL` 实测）**：空板结束 = 49；只放对 1 块 = 60；放到错误槽位 = 42（**比空板还低**）；三块全放对（显式朝向）= 78；同名排列改用 `auto_rotate` = 100。

## 5. 结论

四条假设，**三条被证伪，一条成立**：

1. 没有结构化颜色字段，且**相机不可控**——这意味着所有"固定像素框标定"类解法被永久排除，不是"难"，而是"在这个接口下不成立"。
2. `put_down_sth` 不提供对错信号，唯一的反馈是**局末分数**。
3. `auto_rotate=True` 把"朝向"这个自由度消掉了，问题收敛为纯指派问题（3! = 6 种）。
4. **undo 可用**，于是"局内试排 + 纠错重放"在物理上可行（实测一次 6 次放置 + 3 次取回 + 5 张近照约 95 秒，远低于 400 秒上限）。

还有一条不显眼但很关键的发现：**错误放置的分数（42）低于空板（49）**。这条负收益后来直接变成了所有解法的默认策略——**校验不通过就不落子**。

## 6. 下一步

既然"看"不可靠、接口又不给对错反馈，那就只剩一个观测量可用：**分数本身**。

下一步的思路是：找一个本地永远只出同一道题的环境，把 6 种排列各跑一局，用分数把真值"测"出来——见 `03-brute-force-truth.md`。
