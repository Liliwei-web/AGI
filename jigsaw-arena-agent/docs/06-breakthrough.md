# 06 · 决定性突破：编号里藏着答案

> 本文记录第 10 轮迭代，也就是整个项目的转折点。
> 关键动作不是"找到新算法"，而是**换了一个提问方式**。

## 1. 当时的处境

已经把"看图"这条路彻底排除，也已经被"单样本经验规则"坑过一次（`05-falsified-hypotheses.md`）。

手里剩下的事实只有这些：

- 3×3 板面的几何是固定的（X=837，Y 155/166/177，Z 88/99/110，格距 11）；
- 每局有 6 块已放、3 块待放，待放块出生在 Y=209 的货架行；
- 每局随机抽 3 格掏空，被掏出的块被挪到货架；
- 板面基准 yaw 每局随机，但 `auto_rotate=True` 能把它消掉（只剩 3! = 6 种指派）。

之前所有轮次都在问：**"这三块应该放到哪？"** 而这个问题必须靠"看图"或者"猜规律"来回答。

## 2. 假设

新假设来自一个视角的切换——不再把题目当成"图案题"，而是当成**"生成器的产物"**：

> 如果生成器是"先按固定顺序生成 9 块放到 9 个固定格位，然后随机挑 3 格掏空并把对应块挪到货架"，
> 那么**块的 `object_id` 就唯一决定了它原本属于哪一格**，与"随机出题"无关。

这个假设的美妙之处在于：它把一个**图像问题**变成了一个**编号问题**。答案不在画面里，而在场景数据里——而场景数据是我们可以可靠读到的（物体列表虽然对颜色无用，但 `object_id` 与 `place_location` 是准的）。

而且它是**可证伪、可自校验**的：如果编号到格位存在一个固定映射，那么同一映射必须同时解释"当局的 6 个已放锚点"和"当局的 3 个空槽"。

## 3. 实验设计

验证分三步，逐步加强：

**第一步：跨题对齐。** 取 3 局不同随机题的初始场景（`logs/recon/probe_*.jsonl` 的 `objects` 字段），按 `object_id` 对齐 9 个拼图块（id 7..15），看"第 k 号块落在哪个格"是否固定。

**第二步：与已验真值互证。** 用静态题的真值（由 `jigsaw_score=100` 验证过：8→(166,110) / 10→(155,99) / 14→(166,88)）去对照第一步得到的表，逐项核对。

**第三步：做成"反解 + 校验"，不写死任何常量。** 这是最重要的一步。实现时不把表写成常量，而是把**规则的形式**写下来，让程序现场反解参数：

```python
def predict(bid, base, rflip, cflip):
    n = bid - base
    if n < 0 or n // 3 > 2:
        return None
    row_idx = (2 - (n % 3)) if rflip else (n % 3)
    col_idx = (n // 3) if cflip else (2 - (n // 3))
    return (rows[row_idx], cols[col_idx])

for base in range(-60, 61):
    for rflip in (0, 1):
        for cflip in (0, 1):
            # 条件 1：必须解释全部 6 个已放锚点
            if any(predict(bid, base, rflip, cflip) != cell for bid, cell in anchors):
                continue
            # 条件 2：3 个待放块的预测格位集合必须恰好等于 3 个空槽集合
            if set(pred.values()) != empty_set:
                continue
            fits.append(pred)
```

验收标准有两条，缺一不可：

1. **锚点全中**——反解出的规则必须能把 6 个已放块全部解释掉（这排除了绝大多数巧合）；
2. **集合相等**——3 个待放块的预测格位集合必须**恰好等于**当局的 3 个空槽（不是"有交集"，是集合相等）。

如果出现多组不同参数都能通过，就记 `solve_id_map_ambiguous` 并**放弃落子**（回到保守策略），而不是硬猜。

第三条件（工程约束）：这套逻辑必须在 `JIGSAW_RULE_FORCE=1` 下可以**绕过查表**单独运行，用来证明"满分不是查表带来的"。

## 4. 原始数据

**跨题对齐的结果**（9 个拼图块，id 7..15，行 = Y，列 = Z）：

| id | 归属格 (Y, Z) | id | 归属格 (Y, Z) | id | 归属格 (Y, Z) |
| --- | --- | --- | --- | --- | --- |
| 7 | (155,110) | 10 | (155,99) | 13 | (155,88) |
| 8 | (166,110) | 11 | (166,99) | 14 | (166,88) |
| 9 | (177,110) | 12 | (177,99) | 15 | (177,88) |

即 `id = 7 + 3*k + j`，其中 `k = 0/1/2` 对应 Z 列 `110/99/88`，`j = 0/1/2` 对应 Y 行 `155/166/177`。

**验证证据：**

| 证据 | 内容 | 结果 |
| --- | --- | --- |
| 静态 train 题（4 次重放） | id ↔ 格位完全相同；真值由 `jigsaw_score=100` 验证 | 与上表逐项吻合 |
| 随机题 `probe_ab7148f208` | 6 个已放锚点是否满足上式 + 预测格位集合是否等于空槽集合 | 全部满足 |
| 随机题 `probe_2e1867567e` | 同上 | 全部满足（且它同时是镜像规则失败的那一局） |
| 随机题 `probe_db749ff1bc` | 同上 | 全部满足 |

**绕过查表的实跑验证**（`JIGSAW_RULE_FORCE=1`，强制走新规则）：

```
placed = {"8": [166, 110], "10": [155, 99], "14": [166, 88]}
→ jigsaw_score = 100, score = 98.98
```

**附带的一次"平反"：** 反推 22:xx 那晚的镜像规则为什么错——在 `probe_2e1867567e` 那局它把 9 与 7 的格位对调了。用新表去对，9 本来就该在 (177,110)、7 该在 (155,110)，对调即 2/3 错。这与当晚 VLM"块图不连贯"的判断一致——**那个不可靠的模型，那一次说的是对的**。

## 5. 结论

1. **题目不是"图案推理题"，而是"生成器的还原题"。** 生成器按固定格序生成 9 块，题目只做两件事：随机挑 3 格掏空、把对应块挪到货架行。所谓"随机出题"只随机了**哪三格被掏空**，没有随机"块与格位的对应关系"。
2. 因此答案为：**对每个待放块，查它自己的 `object_id` 归属格，再把块放到那个格**。不需要看图案，不需要参考海报，不需要大模型。
3. **解法是可证明的，而不是经验性的。** 它与前三代有本质差别：

| 代 | 依赖 | 换题后的表现 | 性质 |
| --- | --- | --- | --- |
| 第一代 查表 | 一道题的答案常量 | 直接失效 | 背题 |
| 第二代 镜像规则 | 1 个样本上的巧合 | 2/3 错 | 经验猜测 |
| **第三代 反解** | 场景自身的编号结构 + 一致性校验 | 5/5 通过 | **可证明** |

4. **不写死常量这一点是刻意的。** 把规则写成"参数化的形式 + 现场反解 + 双向校验"，换来三个好处：换了题目/换了 id 批次依然自适应；规则被锚点与空槽双重约束，不会退化成一个万能猜测；校验不通过时有明确的保守回退（留空板），不会硬猜。
