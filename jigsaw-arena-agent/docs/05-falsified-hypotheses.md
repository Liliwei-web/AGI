# 05 · 被证伪的假设：五条走不通的路

> 本文记录第 4–6 轮与第 9 轮迭代。这些轮的产出全是**否定结论**，但它们决定了最终解法长什么样：
> 每一条被排除的路，都在缩小"答案可能藏在哪"的范围。

## 1. 当时的处境

第二阶段的处境很尴尬：**本地已经满分，但满分没有信息量**。

查表法在 `train` 上永远 100 分，于是本地再也无法区分"真解法"和"背题"。唯一的检验场是正式 `test` 模式——而它每次随机抽题、分数加密上传，本地读不出来。

同时，正式模式已经观察到两种不同的随机布局：

- A) 空槽 = 中列 `(155,99) / (166,99) / (177,99)`
- B) 空槽 = `(166,99) / (166,110) / (177,110)`

共同点是格距固定（Y 155/166/177 × Z 88/99/110）、6 个锚点已正确摆放、3 个待放块出生在 Y=209 行、板面基准 yaw 每局变、可见 id 与图案每局重排。

既然"背题"不行，就必须找一条**能从图像推出指派**的路。以下五条候选依次被验证。

## 2. 假设

| 编号 | 假设 | 期望的信号 |
| --- | --- | --- |
| V1 | 块的图案"指纹"可分，可用于匹配 | 同块自洽相似度显著高于错配 |
| V2 | 板面上的**接缝连续性**可判定排列对错 | 正确排列的接缝跳变显著小于错误排列 |
| V3 | 参考海报可作为每格的"期望图案码" | 海报格与板上对应格匹配度显著高于错配 |
| V4 | 视觉大模型能直接判断"哪组更连贯" | 判对率显著高于随机 |
| V5（第二代解法） | 生成器按**固定镜像顺序**摆放 | 货架 Z 升序块 ↔ 空槽 Z 降序格 |

## 3. 实验设计

| 编号 | 实验设置 | 度量 |
| --- | --- | --- |
| V1 | 逐块放入首空槽 → 近距读图案 → undo 放回；中心 48×48px RGB 直方图 | 余弦相似度（同块 vs 错配） |
| V2 | 同站位连拍空槽邻接中点，A（正确排列）/ B（错误排列）两轮对比 | 接缝两侧条带的色均值差 |
| V3 | 两个站位对参考海报（obj16）各拍一帧；对每张图在 7 种镜像/转置映射 × (cx,cy,P) 上粗搜 + 精调 | 9 格平均 cosine；另做"海报逐格近距帧 vs 板上指纹"的 48px 直方图交叉矩阵 |
| V4 | 把裁剪图/整帧交给 `deepseek-flash`（`api.deepseek.com/v1`，带 `detail` 字段）判"哪组连贯" | 反复多轮，人工比对对错 |
| V5 | 用当局的 1 个样本推出镜像规则，写成 `JIGSAW_RULE=1` 回退分支 | 在随机题 `test` 局上看落子结果 |

## 4. 原始数据

**V1 块指纹：一半可用，但关键的一半不可用。**

- 有效：同块自洽 0.95+，错配通常 < 0.79 —— **块的图案码本身是可读的**，且能完全恢复真值（10→(155,99) / 14→(166,88) / 8→(166,110)）。
- 无效：整格/邻居均值直方图、"空槽底板"直方图区分度极弱，正确排列只排在第 1–3 名，margin 仅 ~0.005–0.03。
- 致命限制：**只在块入槽后、近距帧上读得到**。货架位（Y=209）与拿在手上采样都只显示素面（米黄/浅灰/黑 ≈ 10%），图案正面**只在块安装到板上时露出**。所以指纹只能用于"放后校验"，不能用于"放前匹配"。

**V2 接缝连续性：一个方向有信号，另一个方向没有。**

- "横向扫描"档：A≈5.2 / B≈16.8，比值 3.3，9 条缝方向一致；
- 另一扫描方向：A≈2.2–2.6 / B≈1.8–1.9，**无区分度**。
- 更根本的问题：由于瞄准无效（见 `02-recon.md`），它拍到的其实是"同一站位的同一画面"，这个度量的物理含义无法确认——**无法判断它量的是接缝还是画面内容差异**。不能作为判据。

**V3 参考海报标定：两轮实验都失败。**

- 宽幅单帧几何标定：两个站位最优对角线 cosine 仅 **0.32–0.38**，且两站位的最优映射族不一致（站位 1 偏转置族、站位 2 偏镜像族）；另一轮更糟，`best flipRC ≈ 0.397`，中排条目近 0（0.057）。
- 反证实验 2（更严格，同局同题）：直接比较"海报逐格近距帧"与"板上同格"的 48px 直方图矩阵，row0 三格普遍落在 0.5–0.99，**错配对经常 > 0.9**（板上 (0,2) 与海报 (0,1)/(0,2) 都是 0.98+）；最优 3 格双射平均 0.775，与次优**几乎无间隔**。
- 结论：海报与板上是"同图不同缩放/渲染"，像素级直方图无法唯一配对。方案 A 的前提证伪，放弃。

**V4 大模型判图：不可靠。**

- 通路本身是通的（`deepseek-flash` 支持图片输入，`image_url` 必须带 `detail` 字段，否则报 `Unsupported image_url format`）。
- 但判断反复出错，甚至出现"把错的说成对"。
- 唯一一次有价值的输出值得记下来：在某局它输出**"不是山羊图，是角蛙/青蛙图，且不连贯"**——后来证明，它说"不连贯"这件事是对的（那局用的正是下面 V5 的错误规则）。

**V5 镜像顺序规则：单样本规律的代价。**

- 观察来源是 `train` 静态题：待放块按出生行 Z 升序为 8(Z=82) → 10(Z=96) → 14(Z=110)；正确答案是 8→(166,110) / 10→(155,99) / 14→(166,88)，用 Z 表示即 82→110、96→99、110→88，也就是**"货架从左到右 = 空槽按 Z 从右到左"**。
- 它只建立在**一个样本**上，而且本地无法验证（`train` 无法换题：`use_static_subjects=false` + `num_subjects=1` 实测仍是同一题，只有 `target_yaw` 每局不同）。
- 为了降低风险，当时的取舍是：猜错的期望不差于留空（三块全放错的历史实测 46–92，空板 49），猜中即 100，所以默认启用（`JIGSAW_RULE=1`）。
- 结果：在随机题 `probe_2e1867567e` 上，它把 9 与 7 的目标格位**对调**，2/3 错。

## 5. 结论

1. **四条视觉路线全部走不通**，而且每一条的失败原因都很具体：指纹只能放后读、接缝度量物理含义不明、海报与板面不同尺度、大模型不可靠。这不是"没调好参数"，是"观测量本身不存在"。
2. V1 与 V2 的失败是**互补**的：指纹可信但拿不到参照物，接缝有信号但无法定位。两者单独都不足以构成判据。
3. **V5 是项目里最值得记住的教训**：一个只建立在 1 个样本上、且在当前环境下**无法证伪**的规律，不能当结论用。它的实际表现（2/3 错）比"留空板"还差。
4. 顺带得到一个方法论：把假设按"能否本地证伪"分成两类。能证伪的（V1–V4）当场就能淘汰；不能证伪的（V5）必须显式标记为高风险，并给它设计一条更保守的默认策略。
